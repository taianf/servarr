# Servarr on k3s

Migration of the nixflix media stack (Sonarr, Radarr, Lidarr,
Readarr, Prowlarr, qBittorrent, Jellyfin, Jellyseerr, Bazarr,
Cleanuparr, FlareSolverr, Recyclarr) from NixOS systemd services
to a single-node k3s cluster, deployed via `helmfile`.

The cluster runs **side-by-side** with nixflix: both stacks share
`/data` (media + downloads + state) and are reachable concurrently
on different hostnames. After the new stack is verified, nixflix
can be removed and the iptables forward in `services.k3s-servarr`
flipped on so the `:30080` port suffix drops off the URLs.

## Why k3s + helmfile

- **k3s single-node** — Traefik + servicelb + local-path are
  pre-installed; one `nixup` brings the whole cluster up as a
  supervised systemd service. Heavier distributions (Talos, full
  kubeadm) are overkill for one host.
- **helmfile** — the *arr apps are all 10-line values overrides
  of one chart (kubitodev/servarr). helmfile gives us a single
  YAML to apply, diff, and roll back. No GitOps server required
  for a single-node stack; add ArgoCD later if needed.
- **hostPath** — `/data` is a single host directory, mounted the
  same way into every pod. *arr apps need downloads and library
  on the same filesystem (hardlinks, atomic moves); hostPath is
  the simplest way to guarantee that.

## Host / NixOS setup

The k3s side is wired into the dotfiles repo as a NixOS module.
See `nixos/k3s.nix` (in the dotfiles worktree branch
`feat/k3s-servarr-migration`). The module:

- Enables `services.k3s` with role=server.
- Writes a `HelmChartConfig` to `/var/lib/rancher/k3s/server/manifests/traefik-config.yaml`
  so the bundled Traefik chart binds to **NodePort 30080/30443**
  instead of 80/443 — keeps nixflix's nginx on 80/443 during the
  side-by-side phase.
- Adds `*.k8s.nixflix` to `/etc/hosts` (resolved to 127.0.0.1,
  so each `*arr` URL is `http://<service>.k8s.nixflix:30080`).
- Optionally adds an iptables forward (set `ingressForward = true`
  in `nixos/configuration.nix`) once nixflix is removed.

The `hostPath` layout assumes the same `/data` tree as nixflix:
`/data/media/{movies,tv,music,books}`, `/data/downloads/{complete,incomplete}`,
`/data/.state/<app>`. The NixOS module sets PUID=1000 / PGID=169
(host's `media` group GID) on every *arr pod so files are
read/writable by both stacks.

## Bring-up

```bash
# 1) In the dotfiles worktree: rebuild the host.
cd ~/dotfiles
nixup                                # enables k3s, writes Traefik
                                     # HelmChartConfig, sets up /etc/hosts

# 2) Wait for k3s to be ready.
sudo k3s kubectl get nodes
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
mkdir -p ~/.kube && sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown taian:users ~/.kube/config

# 3) In the servarr workspace: render secrets + deploy.
cd /home/taian/workspaces/servarr
bin/deploy                           # sops decrypt + apply static
                                     # manifests + helmfile + Jobs

# 4) Verify.
bin/status
```

## URL map

During the side-by-side phase, the *arr UIs are reachable at:

| Service       | URL                                                  |
| ------------- | ---------------------------------------------------- |
| Sonarr        | http://sonarr.k8s.nixflix:30080                      |
| Radarr        | http://radarr.k8s.nixflix:30080                      |
| Lidarr        | http://lidarr.k8s.nixflix:30080                      |
| Readarr       | http://readarr.k8s.nixflix:30080                     |
| Prowlarr      | http://prowlarr.k8s.nixflix:30080                    |
| qBittorrent   | http://qbittorrent.k8s.nixflix:30080                 |
| Jellyfin      | http://jellyfin.k8s.nixflix:30080                    |
| Jellyseerr    | http://jellyseerr.k8s.nixflix:30080                  |
| Bazarr        | http://bazarr.k8s.nixflix:30080                      |
| FlareSolverr  | http://flaresolverr.k8s.nixflix:30080                |
| Cleanuparr    | http://cleanuparr.k8s.nixflix:30080                  |

After nixflix is removed and `services.k3s-servarr.ingressForward = true`
is enabled, the `:30080` port suffix drops off and the URLs are
the bare hostnames on port 80.

## Re-running wiring Jobs

The Jobs are idempotent and safe to re-run:

```bash
bin/apply-jobs                       # run all Jobs
bin/apply-jobs seerr                 # re-run seerr-setup
bin/apply-jobs prowlarr              # re-run prowlarr-applications + prowlarr-indexers
bin/apply-jobs jellyfin-connect      # re-run all three *arr-jellyfin-connect Jobs
```

## Cutover (remove nixflix)

```bash
# 1) Verify the k8s side is healthy.
bin/status

# 2) Stop the nixflix systemd units.
sudo systemctl stop --now nginx sonarr radarr lidarr prowlarr \
  qbittorrent jellyfin bazarr seerr recyclarr

# 3) Enable the iptables forward in the NixOS module.
#    Edit nixos/configuration.nix:
#      services.k3s-servarr.ingressForward = true;
#    Then:
nixup

# 4) Update /etc/hosts: drop the *arr aliases, keep *.k8s.nixflix.
#    (The NixOS module adds the *.k8s.nixflix entries; the *.nixflix
#    entries are added by nixflix's nginx module and will go away
#    when nixflix is uninstalled.)

# 5) Remove nixflix from nixos/configuration.nix imports and rebuild.
```

## Open follow-ups

- **Backup**: ratcheted to a NAS (restic CronJob) — not yet
  implemented. The PVC for `recyclarr-config` lives in the cluster;
  the per-app state dirs live on `/data/.state` on the host and
  need an out-of-band backup strategy.
- **Recyclarr custom format scores**: the bootstrap `recyclarr.yml`
  ships with placeholder TRaSH IDs. After the first run, edit
  `/config/recyclarr.yml` on the recyclarr PVC with the full list
  from <https://trash-guides.info>.
- **OpenSubtitles API key**: the Bazarr config wires the
  addic7ed/podnapisi/opensubtitles slots but the OpenSubtitles
  API key still needs to be entered in the Bazarr UI
  (`Settings → Providers → OpenSubtitles.com`).
- **LAN DNS**: the k8s hostnames resolve to 127.0.0.1 via
  /etc/hosts. Off-host LAN clients can reach the *arr UIs at
  `http://<lan-ip>:30080/<host>` — set up dnsmasq on the LAN
  router if you want the bare hostname to work everywhere.
